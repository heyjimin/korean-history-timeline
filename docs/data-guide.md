# 데이터 작성 가이드

모든 데이터는 `data/` 폴더의 JSON 파일이고, 스키마는 [src/data/schema.ts](../src/data/schema.ts)에 있습니다.
수정한 뒤에는 `npm run validate`로 검사하세요. 오류가 있으면 빌드와 배포가 멈춥니다.

## 파일 구조

```
data/
  eras.json          시대 목록 (타임라인 배경 띠)
  places.json        장소 목록 (지도)
  events/<era>.json  시대별 사건 목록
  people.json        인물 목록
```

## 사건 선정 기준

### 무엇을 사건 하나로 볼까

- 날짜(최소한 연도)를 특정할 수 있고, 한두 문장으로 "무슨 일이 있었는지" 설명할 수 있으면 사건 하나로 둔다.
- 긴 기간에 걸친 일(전쟁, 사절 파견의 연속)은 **상위 사건**으로 두고, 그 안의 개별 사건을 `part_of`로 잇는다.
  - 예: `임진왜란` ← 한산도 대첩, 행주 대첩, 정유재란 / `정유재란` ← 명량 해전, 노량 해전
- 제도의 설치·폐지, 조약 체결, 왕의 즉위처럼 "한 시점의 결정"은 각각 사건 하나다.
- 인물 자체는 사건으로 넣지 않는다. 인물은 사건 설명 안에서 다룬다.

### core와 detail 나누기

| | core (핵심) | detail (상세) |
|---|---|---|
| 기준 | 교과서 단원 제목이나 소제목에 나올 만한 사건, 이후 흐름을 바꾼 사건 | core 사건을 이해하는 데 도움이 되는 경과·배경 사건 |
| 예 | 임진왜란, 한산도 대첩, 훈련도감 설치, 기유약조 | 부산진성 전투, 탄금대 전투, 칠천량 해전 |
| 목표 비율 | 시대별 사건의 약 30~40% | 나머지 |

`수능빈출` 태그는 importance와 별개입니다. 수능 연표에 자주 나오는 사건이면 detail이어도 붙일 수 있습니다.

### 시대별 밀도 목표

상세 연표 기준 전체 약 400~500건을 목표로 합니다. 시대별로 대략 다음 비중을 맞춥니다.

| 시대 | 목표 사건 수 |
|---|---|
| 선사 ~ 고조선 | 15~20 |
| 삼국 ~ 남북국 | 60~80 |
| 고려 | 60~80 |
| 조선 | 100~120 |
| 근대 | 60~80 |
| 일제 강점기 | 50~60 |
| 현대 | 50~60 |

## 필드 작성 규칙

### id
- 영문 소문자 kebab-case. 한 번 정하면 바꾸지 않는다 (주소와 관계가 깨진다).
- 같은 이름의 사건이 여러 번 있으면 연도나 차수를 붙인다: `jinju-battle-1`, `tongsinsa-1607`.

### date
- 기원전은 음수: 기원전 2333년 → `{ "year": -2333 }`. 0년은 없다.
- 아는 만큼만 적는다. 월을 모르면 `{ "year": 1593 }`.
- 조선 시대까지 사료의 월·일은 대부분 **음력**이다. 기본값이 `"lunar"`이며, 양력이면 `"calendar": "solar"`를 적는다. 근대 이후(1896년 양력 도입 이후)는 양력으로 적는다.
- 연도 자체가 추정이면 `"approximate": true` ("4세기경").

### summary와 detail
- `summary`: 2~3문장. 수험생이 훑어보는 용도. "누가, 언제, 무엇을, 결과는"이 드러나게.
- `detail`: 선택. 배경·경과·의의를 일반 독자에게 설명. 문단은 빈 줄로 나눈다.
- **문장은 직접 쓴다.** 나무위키 문장을 각색했다면 그 문서를 `"kind": "adapted"` 출처로 넣는다. 위키백과 문장은 옮기지 않는다 ([CONTENT-LICENSE.md](../CONTENT-LICENSE.md)).

### categories
- `정치`, `제도`, `전쟁`, `외교`, `경제`, `사회`, `문화` 중에서 고른다.
- **맨 앞의 분야가 타임라인 세로축의 띠를 정한다**: 정치·제도 / 전쟁·외교 / 경제·사회 / 문화. 가장 중요한 분야를 맨 앞에 적는다.
  - 예: 훈련도감 설치는 `["제도", "전쟁"]` → 정치·제도 띠, 의병 봉기는 `["전쟁", "사회"]` → 전쟁·외교 띠

### relations
사건 쪽에 **나가는 방향**으로 적습니다. 반대 방향(하위 사건 목록, 원인 등)은 화면에서 자동으로 계산합니다.

| type | 뜻 | 방향 | 예 |
|---|---|---|---|
| `part_of` | 하위 사건 | 하위 → 상위 | 한산도 대첩 → 임진왜란 |
| `followed_by` | 시간상 이어지는 사건 | 앞 → 뒤 | 옥포 해전 → 한산도 대첩 |
| `led_to` | 원인과 결과 | 원인 → 결과 | 강화 협상 결렬 → 정유재란 |
| `related` | 그 밖의 관련 | 아무 쪽 (한 번만) | 한산도 대첩 ↔ 행주 대첩 (3대첩) |

- 상위 사건(`part_of`)은 하나만 둔다.
- 관계에 이유가 있으면 `note`에 짧게 적는다.

### people (사건 쪽)
- 사건과 직접 관련된 인물의 id 목록. 인물은 `people.json`에 먼저 등록한다.
- 사건을 일으키거나 이끈 사람, 그 사건의 결과를 상징하는 사람만 넣는다 (스쳐 지나가는 인물은 넣지 않는다).

### people.json (인물)
- `name`: 가장 널리 쓰는 이름. 왕은 묘호(예: 세종), 그 밖에는 본명.
- `aliases`: 호, 시호, 다른 이름 (예: 이순신 → 충무공). 검색에 쓰인다.
- `born`, `died`: 모르면 비운다. 기원전은 음수. 추정이면 `"approximate": true`.
- `role`: 한 줄 소개 (예: "조선의 수군 장수"), `summary`: 1~2문장.
- 전승 속 인물(단군왕검 등)은 역할에 "(전승)"을 붙인다.

### locations
- 장소는 `places.json`에 먼저 등록하고 id로 참조한다.
- `role`: `main`(주 무대), `start`/`via`/`end`(경로). 경로를 선으로 이으려면 `"route": true`.
- 장소를 특정하기 어려운 사건은 비워 둔다.

### places.json의 precision
- `exact`: 성, 궁궐처럼 지점이 분명한 곳
- `approx`: 해전 해역처럼 대략적인 곳
- `region`: 의병 활동 지역, 외국 도시처럼 넓은 지역
